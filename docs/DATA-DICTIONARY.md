# 业主表决簿数据字典

## 来源文件

| 字段 | 定义 |
|---|---|
| 表决议案 | 文本主键，保留前导零。跨业务键不汇并记录。 |
| 修订号 | 正整数。最高版优先；最高同版字段冲突或存在同版、更新版的未采信记录时隔离，旧版无法接替。 |
| 提交时间 | ISO 8601，必须带 UTC 偏移量。标准化后展示 UTC。 |
| 原始备注 | 可空，允许引号内换行。 |
| 议案类别、产权单元、表决票 | 必填字段。多项字段用半角分号隔开，显式空集合用 `无`。 |

识别 `UTF-8`、UTF-8 BOM 与独立的 `GB18030` 文件。`业务编号`、`版本`、`更新时刻`、`备注` 为旧版表头别名。新旧名同时出现会被拒绝。`-`、`N/A`、`NULL`、`未知` 和空串均按必填值缺失处理。物理行号指 CSV 逻辑记录起始行。

## 计算字段

产权写成 `房屋:面积:业主=份额+业主=份额`，每套份额合计 100%。票写成 `业主:赞成或反对或弃权`。

本项目按样例议事规则计算。参与需同时达到业主数和面积的 2/3，一般议案赞成须过半，特别议案须达到 3/4。

数值在服务端以十进制定点方式计算，对外按字符串传输。单文件上限 128 KiB，复合字段最多 240 个项目，个别字段还有业务上限。格式无法恢复的 CSV 整批拒绝，列数、缺字段、来源冲突和业务条件错误逐条隔离。

## 复算与外部清单

外部清单包含 `表决议案` 和 `外部记录值(平方米)`，允许省略不在对账范围内的键。同一键重复会拒绝该清单。结果数值单位为 **平方米**。差值按本次复算减外部记录，缺一侧时差值计算以 0 占位并保留缺失原因。

同一对输入字节与规则版本生成同一批次，导出包含两个文件摘要、证据行、单边差异和复核修订记录。复核保存前检查当前版本，在有隔离、差异或退回时必须填写意见。

## 公示批次（多楼栋合并）

一次公示批次由 1–12 份楼栋送审文件与一份外部账组成，请求体为 `sources: [{name, data|data_base64}, ...]` 与可选 `book`。每份文件独立完成导入、归一并保留原始字节（`notice_sources` 表），再按业务键跨文件选最高修订：后到的旧表只登记为 `SUPERSEDED`，不会把已通过议案翻回旧结论。

- 批次指纹只取各来源字节摘要的排序集合加规则版本与外部账摘要，因此同组文件调换顺序或原样重跑得到同一 `notice_id`；幂等写入保证不新增批次、不重复来源记录。
- `motions[]` 逐议案给出 `adopted`（采信的来源 `source_id`、行号、修订号、参与/赞成人数与面积、双门槛结论）与 `history[]`（每个修订的送审痕迹、独立复算结论、`changed` 结论翻转标记、阻断码）。
- `POST /api/notices/{id}/seal` 封存批次，重复封存返回 `NOTICE_SEALED`。封存后补传先走 `POST /api/notices/{id}/amendments`：只用原封存文件加补传重算，返回 `affected`（含逐字段 `field_changes` 与 `conclusion_changed`）和 `blocked`（高修订无法采信时的原因），不写库、不产生新批次。
- 计票员重新确认后调 `POST /api/notices/{id}/confirm` 才形成新公示批次；原封存批次与其全部送审文件原样保留，新批次的补传来源接续编号（`dong-{N+1}`）避免来源标识冲突。
